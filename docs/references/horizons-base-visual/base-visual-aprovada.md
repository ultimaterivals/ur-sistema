# Base Visual Aprovada — Horizons

## Decisão técnica

O export do Hostinger Horizons foi usado apenas como referência visual. Ele não será aplicado diretamente ao projeto oficial porque está em React/Vite/JSX, enquanto o projeto oficial utiliza Next.js/TSX.

A referência aprovada deve orientar futuras sprints visuais, mas qualquer implementação final deve ser feita no repositório oficial com controle, QA e preservação das integrações existentes.

## Direção visual aprovada

O Ultimate Rivals deve parecer:

> “Uma liga de quadra de areia com alma de game, narrativa de temporada e acabamento premium.”

## Elementos visuais aprovados

- Visual mobile-first.
- Fundo preto/grafite.
- Dourado como cor de destaque.
- Cards grandes e premium.
- Glow dourado moderado.
- Botões arredondados, mas com peso esportivo.
- Hierarquia visual forte.
- Hero de impacto.
- Cards de jornada.
- Estética de ranking.
- Badges, escudos e tags.
- Sensação de temporada.
- Pegada gameficada sem parecer jogo infantil.
- Blocos com ritmo visual e leitura clara.
- Imagens ligadas a quadra de areia.
- Atmosfera de arena, disputa e comunidade.

## Elementos que não devem ser copiados

- Stack React/Vite.
- Estrutura de projeto do Horizons.
- Lógica fake.
- Dados fictícios apresentados como reais.
- Promessas de carreira profissional.
- Promessas de dinheiro.
- Promessas de prêmio garantido.
- Promessas de benefício garantido.
- Termos incorretos como Regional.
- Layouts que mudem demais a estrutura oficial.
- Qualquer código que quebre formulários ou integrações.

## Paleta visual

Usar como referência:

- Preto profundo.
- Grafite.
- Dourado.
- Amarelo elétrico controlado.
- Branco/off-white.
- Cinza claro para textos secundários.
- Bordas com transparência.
- Glow dourado sutil.

## Tipografia

A tipografia deve buscar identidade esportiva:

- Mais forte.
- Mais competitiva.
- Menos arredondada.
- Com aparência de liga, ranking, arena e temporada.
- Boa leitura mobile.
- Sem parecer infantil.
- Sem parecer fantasia.
- Sem prejudicar textos longos.

- Futevôlei.

## Regras de preservação

Em futuras sprints:

1. Não recriar o site do zero.
2. Não reorganizar a Home inteira sem necessidade.
3. Não alterar backend.
4. Não alterar formulários.
5. Não alterar Supabase.
6. Não alterar Apps Script.
7. Não alterar Sheets.
8. Não alterar CRM.
9. Não alterar endpoints.
10. Não alterar hashes.
11. Não alterar nomes de campos.
12. Não alterar lógica de cadastro.
13. Não alterar next-env.d.ts.
14. Não alterar package.json sem justificativa.
15. Não commitar arquivos .patch.
16. Preservar mobile-first.
17. Preservar preto/dourado.
18. Preservar clareza estratégica.
19. Validar sempre em múltiplos viewports.
20. Fazer ajustes por sprint pequena e controlada.
